# 项目方案与进度

## 背景

本项目整理自 2026-10-23 的“修复 Codex 项目排序”聊天。
该次调查中，聊天的最近更新排序没有让侧边栏项目持续按活动时间上移；
曾经通过应用工具完成一次手动重排。

用户认可的方向是：对话结束事件触发检查，仅在项目顺序确实变化时执行重排。

## 计划中的处理流程

```text
对话结束事件
  → 读取当前项目清单、分区顺序和对话活动时间
  → 计算默认项目区域的目标顺序
  → 顺序一致：退出
  → 顺序不同：通过已确认可用的客户端接口更新
```

同一项目已经位于首位时，后续对话通常只需要一次本地检查。
时间相同的项目保留已有相对顺序；没有活动记录的项目排在有活动记录的项目之后。

## 阶段

1. **已完成：仓库初始化。** 建立项目说明、开发规则和 Git 基线。
2. **已完成：整理排序规划器。** 迁入前期只读脚本，真实聊天数据和状态快照留在原目录。
3. **待完成：确认客户端写入接口。** 验证项目顺序更新与侧边栏刷新，再实现写入适配。
4. **待完成：接入对话结束事件。** 验证触发方式、去重、并发处理与错误退出行为。

## 当前限制

前期只读脚本可以计算目标顺序，但无法独立完成客户端更新。
前期调查尚未确认 Hook 可以调用的侧边栏顺序写入接口；
聊天中的排序工具也不能直接视作本地脚本可用的 API。
现阶段没有安装或启用 Hook、常驻进程、定时任务。

接入客户端前，必须重新核对当前版本的接口及数据结构。
私有客户端字段和数据库结构可能变化，现有脚本不是跨版本兼容承诺。
